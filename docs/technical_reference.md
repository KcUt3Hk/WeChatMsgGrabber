# 技术说明文档

## 1. 文本识别置信度 (Confidence Score) 说明

`confidence_score` 字段表示系统对OCR识别结果的置信程度，取值范围为 0.0 到 1.0。

### 1.1 计算逻辑

本项目使用 **PaddleOCR (PP-OCRv4)** 模型进行文字识别。

1.  **单行置信度**：
    *   OCR 模型采用 CRNN (Convolutional Recurrent Neural Network) 架构。
    *   在识别阶段，模型对每一个字符位置输出一个概率分布（Softmax）。
    *   单行文本的置信度通常计算为该行所有字符预测概率的平均值（或 CTC 解码路径的联合概率）。
    *   该分数直接反映了模型对当前图像区域包含特定文字的“确信度”。

2.  **消息级置信度**：
    *   一个聊天气泡（Message）可能包含多行文本（多个 OCR 区域）。
    *   `Message.confidence_score` 计算公式为：
        $$
        \text{Score}_{\text{msg}} = \frac{\sum_{i=1}^{N} \text{Score}_{\text{line}_i}}{N}
        $$
    *   即所有组成该消息的文本行置信度的**算术平均值**。

### 1.2 评分维度与权重

*   **图像清晰度**：模糊、低对比度的图像会导致字符特征提取困难，降低分数。
*   **文字完整性**：文字被遮挡或截断会显著降低分数。
*   **字体标准度**：手写体或艺术字体的识别置信度通常低于标准印刷体。
*   **语言模型匹配**：虽然 PP-OCR 主要基于视觉特征，但隐式的语言模式也会影响最终概率（例如常见词组的置信度通常更高）。

### 1.3 分数与准确性的关联

根据实测经验（基于通用聊天记录数据集）：

| 分数范围 | 准确性预期 | 建议处理 |
| :--- | :--- | :--- |
| **> 0.95** | **极高** | 几乎无错误，可直接采信。 |
| **0.85 - 0.95** | **高** | 可能存在个别标点或形近字错误（如“日”vs“曰”）。 |
| **0.70 - 0.85** | **中** | 可能存在部分乱码或生僻字错误，建议人工复核。 |
| **< 0.70** | **低** | 极高概率为误识别（如将背景纹理误认为文字），或图片极其模糊。 |

### 1.4 验证方法

本项目的置信度直接来源于业界验证过的 PaddleOCR 预训练模型，其在多种公开数据集（如 ICDAR2015, CTW1500）上经过了广泛的精度验证。在实际应用中，可通过以下方式验证合理性：

*   **抽样复核**：随机抽取 100 条消息，人工标注是否正确，统计不同分数段的准确率（Accuracy）。
*   **阈值过滤**：观察在过滤掉 `< 0.8` 的结果后，剩余内容的可用性提升情况。

## 2. 时间戳处理逻辑 (Timestamp Parsing)

### 2.1 修正前的问题
*   所有消息的时间戳均默认为扫描时间（`datetime.now()`），导致无法还原历史对话的真实时间轴。

### 2.2 修正后的逻辑
*   **上下文时间 (Context Time)**：引入状态变量 `current_context_time`。
*   **系统时间消息识别**：
    *   解析器会优先识别微信的系统时间分隔符（如 `"9月28日 晚上7:22"`, `"昨天 10:05"`）。
    *   一旦识别到时间消息，解析该字符串为标准 `datetime` 对象，并更新 `current_context_time`。
    *   该消息被标记为 `MessageType.SYSTEM`。
*   **时间传播**：
    *   后续的普通文本消息（TEXT, SHARE, IMAGE 等）将继承当前的 `current_context_time`。
    *   直到遇到下一个时间分隔符，上下文时间再次更新。

### 2.3 支持的格式
*   **完整日期**：`2025年12月6日 10:00`
*   **当前年份日期**：`9月28日 晚上7:22` （自动补全当前年份）
*   **相对日期**：`昨天 10:00`, `星期五 14:30` （基于参考时间回溯）
*   **中文时段**：支持 `凌晨`, `早上`, `上午`, `中午`, `下午`, `晚上` 的 12小时制转 24小时制逻辑（如 `晚上7点` -> `19:00`）。

## 3. OCR 文本修正 (Correction)

针对金融/区块链领域的特定术语，在 OCR 识别后增加了后处理层：

*   **词表替换**：基于预定义的混淆词表进行强制替换。
    *   `廊家的` -> `哪家的`
    *   `区快链` -> `区块链`
    *   `比特比` -> `比特币`
    *   `以太妨` -> `以太坊`
*   **生效时机**：在文本行聚合之前立即执行，确保后续的正则匹配（如关键词检测）基于修正后的文本。
